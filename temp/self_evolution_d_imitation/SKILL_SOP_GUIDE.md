# D 类 Skill / SOP 沉淀说明

## 一、考察目标

D 类的重点不只是生成一次正确 CSV，而是观察 Agent 能否把从样板中归纳出的经验转化为后续可复用的本地产物。

同组工作目录在 D-1、D-2、D-3 之间不重置，因此 Agent 可以在第一题完成后继续保留自己的脚本、规则配置、测试结果和笔记。

## 二、建议观察的沉淀产物

### 1. 规则配置

用于记录从样板中确认的参数，例如：

- 输入字段与输出字段的映射；
- 日期输入格式与输出格式；
- 金额精度；
- 缺失数量处理；
- 排序字段；
- 合计标签。

配置应与具体数据分离，不能写死某一题的单号、金额或答案。

### 2. 通用转换器

转换器应支持：

1. 读取 CSV；
2. 根据配置识别字段；
3. 转换日期；
4. 处理缺失数量；
5. 计算金额并按指定精度舍入；
6. 按指定字段稳定排序；
7. 追加合计行；
8. 用与样板一致的编码和换行写出结果。

### 3. 样板回放

Agent 可以使用同一转换器重新处理样板输入，再把生成结果与样板输出逐字节比较。

只有全部样板回放一致，才把转换器应用到当前待办数据。这种做法能减少反复提交错误答案的回合。

### 4. 规则笔记

笔记可以记录：

- 已确认规则；
- 尚未确定的候选规则；
- 舍入方式；
- 排序是否稳定；
- 输出编码和换行；
- 后续题需要参数化的部分。

## 三、三题中的复用路径

### D-1

Agent首次比较三组样板，形成：

```text
基础规则配置 + 通用转换器 + 样板回放方法
```

### D-2

D-2 的业务骨架不变，但字段名和金额精度变化。理想 Agent 不重写整个程序，只增加一套配置：

```text
字段映射变化
日期输入格式变化
金额精度变化
合计标签变化
排序字段由“营地”映射为“仓区”
```

### D-3

D-3 回到 D-1 规则，但只提供两组样板。理想 Agent 应直接加载 D-1 配置，先回放现有两组样板，再处理新数据。

## 四、什么算有效 Skill

有效 Skill 应满足：

- 不包含目标答案；
- 不硬编码样板单号；
- 输入、输出路径可更换；
- 字段名、精度和标签可配置；
- 能回放样板；
- D-3 能直接复用 D-1 配置。

以下不算有效 Skill：

- 手工写死 `answer_d1.csv`；
- 只记录某几个单号的最终顺序；
- 每题复制一份完全独立的一次性脚本；
- 从组织方标准答案文件反向复制结果。

## 五、评分中的体现

Skill 文件本身不作为答案，不单独给分。它通过以下指标体现：

- D-2、D-3 的 Judge 回合是否明显少于 D-1；
- 后续题是否一次生成正确 CSV；
- 是否减少重复读取样板和重复修改脚本；
- 过程审计中是否存在参数化、可回放的本地产物。

建议预期：

| 题目 | 预期行为 | 回合参考 |
|---|---|---:|
| D-1 | 探索并形成 Skill/SOP | 8～15 |
| D-2 | 扩展配置后复用 | ≤4 |
| D-3 | 直接复用 D-1 配置 | ≤3 |

实际阈值应由目标 Agent 多次测试后标定。

## 六、给选手的提示边界

任务卡可以告诉选手：

- 同组工作目录不重置；
- 可以保留此前创建的文件；
- 后续还有同类任务。

任务卡不应直接告诉选手：

- 完整隐藏规则；
- 正确排序结果；
- 标准转换代码；
- 必须创建哪些具体文件。

是否主动把经验沉淀成 Skill/SOP，仍然是 Agent 能力的一部分。
