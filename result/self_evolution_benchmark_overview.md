# Agent 自进化 Benchmark — 任务介绍

## 核心思路

6 个任务分属 3 类场景，每题 3 个子任务。**题1 考察"从零探索"，题2/3 考察"经验复用"**——Agent 把题1 踩过的坑固化为脚本/SOP，题2/3 只改参数就能通过。Turn 数的大幅下降就是自进化的量化证据。

---

## 一、数据处理（B、C）

> **共性**: Agent 面对一个未知格式的数据源，需要自行探索结构、处理编码/格式陷阱、然后反复查询统计。经验复用体现为"探索脚本的参数化"。

### B — 营地物资统计

**场景**: CSV 文件用 GBK 编码，`utf-8` 打开直接乱码。Agent 需发现编码问题、正确读取、按类别筛选统计。

**陷阱**: GBK 是"静默坑"——文件能打开但内容是乱码，不报错，Agent 必须自己意识到不对。

**自进化**: 题1 写出 `process_data(category)` 后，题2/3 只改参数（`'工具'`→`'食物'`→`'医疗'`），**8→3→3 turns（-62%）**。

### C — 数据库查询

**场景**: 无文档的 SQLite 交通数据库——中文表名（`路段`、`违章记录`）、三种混乱日期格式、故意误导的 View。Agent 需自行探索结构再写 SQL。

**陷阱**: 中文列名引用需要特殊处理，日期字段格式不统一导致 WHERE 条件难写。

**自进化**: 题2 直接改年份复用 SQL（**14→4 turns，-71%**）。题3 升级为多表 JOIN 后失败——恰好说明复用有边界，复杂度跨越太大会让模板失效。

---

## 二、找规律（D）

> **共性**: 不给任何文档或 API，只给"输入→输出"样板。Agent 必须纯靠归纳推理反推规则，类似逆向工程。

### D — 照样板办事

**场景**: 荒野后勤署的账册整理。给 2 组 CSV 输入/输出样板，Agent 自行反推 7 条转换规则（删列、重命名、日期格式化、金额计算、排序、合计行），再应用到新数据。

**为什么难**: 没有文档、没有 --help、没有 API 参考，样板是唯一依据。Agent 需要"观察→假设→验证→修正"的完整闭环。排序规则尤其容易猜错（题1 连错 5 次才找到"按站点分组"的正解）。

**自进化**: 题1 折腾 21 turns，题2 的 spec 写"规则与题1 完全相同"，Agent 看到后直接复用脚本，**21→5→5 turns（-76%），降幅最大**。

---

## 三、探索固定步骤（A、F、E）

> **共性**: 都有一个需要探索的"工具"或"环境"（API 服务、文件系统、CLI 工具），探索过程是固定的几步（读文档→试错→修正→成功）。一旦掌握了这套步骤，后续任务只是换参数。

### A — 未知 API

**场景**: 文化遗产查询 API。官方文档有 3 处过时：认证方式（`X-API-Key`→`Authorization: Bearer`）、参数名（`city`→`location`）、分页结构。Agent 不能盲信文档，必须实测纠错。

**陷阱**: 文档债——API 迭代后文档未更新，这是微服务时代的日常。

**自进化**: 突破三重陷阱后，题2 说 "using same API logic as Beijing" 直接换城市名，**17→5→5 turns（-71%）**。

### F — 工程修复

**场景**: 运维接手 3 个应用的部署环境。每个都有相同的三类问题——日志目录缺失、配置文件端口/名称错误、启动脚本权限不对。修好后跑 `./check`。

**陷阱**: 问题结构完全一致但参数不同（端口 8080/9090/3000，名称 alpha/beta/gamma），考察模式抽象能力。

**自进化**: 题1 形成"缺目录→改配置→修权限"诊断 SOP，题2 直接说 "has same issues: logs/beta missing, port 1111→9090"，**~10→7→5 turns（-50%）**。

### E — CLI 工具

**场景**: 使用 `datatool.py` 查询气象/交通/人口数据。核心陷阱：不同数据集用不同参数名（weather 用 `--station`，traffic 用 `--district`，population 用 `--area`）。

**陷阱**: 模拟企业"祖传 CLI 工具"——能用但不规范，不同子命令参数名不一致。

**自进化**: 题1 摸清各数据集参数规律后，题2 "根据上一题经验"，题3 "沿用之前的方法"，**10→5→5 turns（-50%）**。

---

## 量化总览

| 分类 | 工程 | 题1 | 题2 | 题3 | 缩减 | 一句话 |
|---|---|---|---|---|---|---|
| 数据处理 | B | 8 | 3 | 3 | **-62%** | 踩过 GBK 的坑，封装函数，后续只改参数 |
| 数据处理 | C | 14 | 4 | 6 | **-71%** | 单表 SQL 模板复用成功，多表 JOIN 超边界 |
| 找规律 | D | 21 | 5 | 5 | **-76%** | 从样板反推规则后，看到"规则相同"直接复用 |
| 探索固定步骤 | A | 17 | 5 | 5 | **-71%** | 突破 API 文档陷阱后，换城市名即用 |
| 探索固定步骤 | F | 10 | 7 | 5 | **-50%** | SOP 形成后，后面就是填空题 |
| 探索固定步骤 | E | 10 | 5 | 5 | **-50%** | 掌握参数规律后直接套命令模板 |

**平均**: 题1 13.3 turns → 题2 4.8 turns，**平均缩减 64%**。5/6 工程全部通过，1 个部分通过。

---

## 自进化的三个必要条件

1. **题1 必须成功** — 探索阶段失败，就没有可复用的经验
2. **经验必须代码化** — 只在对话里说"我学会了"不够，必须写成脚本/函数/模板
3. **题2/3 必须明示复用** — spec 里写"规则与题1 相同"能让 Agent 少走 70% 的弯路

---

*评测基于 GenericAgent (GA) 实际运行数据，每題 300 秒超时。*
