# Agent 自进化 Benchmark — 任务介绍

---

## 一、固定步骤类（探索未知工具→形成 SOP→复用）

> **共性**: 每个任务都有一个需要探索的"工具"或"环境"（API 服务、文件系统、CLI 工具）。探索过程是固定的几步（读文档→试错→修正→成功），一旦掌握，后续任务只需换参数。

### 未知 API — 文化遗产查询

**场景**: 文化遗产查询 API。官方文档有 3 处过时：认证方式（`X-API-Key`→`Authorization: Bearer`）、参数名（`city`→`location`）、分页结构。Agent 不能盲信文档，必须实测纠错。

**陷阱**: 文档债——API 迭代后文档未更新，这是微服务时代的日常。

**自进化**: 突破三重陷阱后，后续城市只需换城市名，**17→5→5 turns（-71%）**。

### 工程修复 — 运维部署修复

**场景**: 运维接手 3 个应用的部署环境。每个都有相同的三类问题——日志目录缺失、配置文件端口/名称错误、启动脚本权限不对。修好后跑 `./check` 验证。

**陷阱**: 问题结构完全一致但参数不同（端口 8080/9090/3000，名称 alpha/beta/gamma），考察模式抽象能力。

**自进化**: 形成"缺目录→改配置→修权限"诊断 SOP 后，后面就是填空题，**10→7→5 turns（-50%）**。

### CLI 工具 — 祖传命令行

**场景**: 使用 `datatool.py` 查询气象/交通/人口数据。核心陷阱：不同数据集用不同参数名（weather 用 `--station`，traffic 用 `--district`，population 用 `--area`）。

**陷阱**: 模拟企业"祖传 CLI"——能用但不规范，不同子命令参数名不一致。

**自进化**: 摸清各数据集参数规律后直接套命令模板，**10→5→5 turns（-50%）**。

## 二、模仿类（看样板→反推规则→复用）

> **共性**: 不给任何文档或 API，只给"输入→输出"样板。Agent 必须纯靠归纳推理反推规则，类似逆向工程。

### 照样板办事 — 账册整理

**场景**: 荒野后勤署的账册整理。给 2 组 CSV 输入/输出样板，Agent 自行反推 7 条转换规则（删列、重命名、日期格式化、金额计算、排序、合计行），再应用到新数据。

**为什么难**: 没有文档、没有 --help、没有 API 参考，样板是唯一依据。Agent 需要"观察→假设→验证→修正"的完整闭环。排序规则尤其容易猜错（曾连错 5 次才找到"按站点分组"的正解）。

**自进化**: 21 turns 痛苦归纳出规则后，看到"规则与上题完全相同"直接复用脚本，**21→5→5 turns（-76%），降幅最大**。

## 三、数据处理类（探索数据格式→封装函数→复用）

> **共性**: Agent 面对一个未知格式的数据源，需要自行探索结构、处理编码/格式陷阱、然后反复查询统计。经验复用体现为"探索脚本的参数化"。

### 数据库查询 — 中文 SQLite

**场景**: 无文档的 SQLite 交通数据库——中文表名（`路段`、`违章记录`）、三种混乱日期格式、故意误导的 View。Agent 需自行探索结构再写 SQL。

**陷阱**: 中文列名引用需要特殊处理，日期字段格式不统一导致 WHERE 条件难写。

**自进化**: 单表 SQL 模板复用成功（14→4 turns，-71%），但多表 JOIN 时模板失效（题3 失败）——恰好说明复用有边界，复杂度跨越太大会让模板失效。

### 营地物资统计 — GBK 编码陷阱

**场景**: CSV 文件用 GBK 编码，`utf-8` 打开直接乱码。Agent 需发现编码问题、正确读取、按类别筛选统计。

**陷阱**: GBK 是"静默坑"——文件能打开但内容是乱码，不报错，Agent 必须自己意识到不对。

**自进化**: 题1 写出 `process_data(category)` 后，后续只改参数（工具→食物→医疗），**8→3→3 turns（-62%）**。
